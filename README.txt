Результат

На учебной VM настроены DHCP, hostname mephi-2026.domain.local и SSH.
Обновление завершено; после перезагрузки используется ядро 6.12.101-1.red80.
Nginx и libcap-ng-utils установлены через dnf. Пакет tcpdump скачан командой
dnf download, подпись проверена, x86_64 RPM установлен через rpm.

Второй диск содержит один раздел ext4 с меткой MEPHI_WEB. Том монтируется
в /mephi-web по LABEL из fstab. Nginx запускается автоматически и зависит
от монтирования этого каталога. GET http://localhost/ возвращает:
Hello from Student: 372396

Пользователи user1, user2, user3 имеют UID 5501, 5502, 5503. Общая группа
developers, SGID и default ACL обеспечивают взаимное чтение и изменение
новых файлов и вложенных каталогов в /data/mephi-2026, в том числе при
umask 077. Curator1 и curator2 (имена в системе: curator1, curator2)
входят в curators с GID 4444: читают, но не создают, не изменяют,
не удаляют и не переименовывают файлы. Постороннему labadmin без sudo
доступ к каталогу запрещён. Проверены все сочетания пользователей.

У tcpdump отсутствует SUID; установлены cap_net_raw,cap_net_admin=ep.
После перезагрузки user1 успешно захватил ICMP на loopback-интерфейсе.
SELinux работает в Enforcing. Правило httpd_sys_content_t для дерева
/mephi-web записано постоянно через semanage fcontext; matchpathcon
подтвердил контексты каталога и страницы.

Для службы login добавлено отдельное правило pam_access, запрещающее
локальный вход группе curators. Глобальная блокировка этих аккаунтов
не применяется. Проверены правильные пароли всех пяти пользователей:
аутентификация успешна, PAM разрешает вход разработчикам и возвращает
PAM_PERM_DENIED кураторам. Журнал также содержит реальные отказы /bin/login.
Финальный воспроизводимый тест вызывает PAM службы login с PAM_TTY=tty8;
он проверяет authenticate/account, но не открывает пользовательскую оболочку.
Тест /bin/login в PTY ранее прошёл для всех пяти пользователей, однако
повторные серии иногда теряли PTY до аутентификации; это не трактовалось
как отказ политики. Соответствующий тест сохранён отдельно.

Парольная политика: минимум 12 символов без уменьшения длины за классы
символов, enforce_for_root, максимальный срок 90 дней. Проверка passwd
от обычного user1 отклонила 11 символов и приняла сильный пароль из 24.
Срок 90 дней подтверждён полями shadow для учебных пользователей,
labadmin и root. Root остаётся заблокированным. В данной сборке chage -l
не выводил сведения, поэтому отдельно приложен безопасный вывод полей
срока действия из shadow в policy-details.out.

  post-reboot.out          состояние системы после итоговой перезагрузки;

history.out получен из настоящей истории Bash. Большинство действий
выполнены помощником через неинтерактивные SSH-сценарии и не попадают
в Bash history; их команды и результаты приложены отдельно. История
не дополнялась вымышленными интерактивными командами. Сценарии являются
журналом реализации: не запускать их все повторно, поскольку ранние
этапы включают разметку диска и создание аккаунтов.

mephi-screenshot.png — настоящий снимок /dev/fb0 с tty8 этой VM после
выполнения команд show_console.sh. Пиксели сохранены в PNG без дорисовки,
обрезки или изменения размера. Исходная консоль tty1 затем восстановлена.

Оговорки для оценки

1. Фактически установлена РЕД ОС 8.0.3 Standard Desktop. Сертифицированная
   редакция не подтверждена. KDE/SDDM и Xorg/Xwayland удалены, используется
   multi-user.target. Это не меняет редакцию дистрибутива на сертифицированную.
   При требовании именно сертифицированной редакции необходимо согласование
   с преподавателем либо повторение настройки на подходящей редакции.
2. В публичном файле shadow второе поле каждой строки заменено на [REDACTED].
   Хеши паролей не публикуются; исходный /etc/shadow на VM не редактировался
   ради экспорта. Остальные поля сохранены. Допустимость очищенной копии
   для формальной проверки следует согласовать с преподавателем.
3. Работоспособность после перезагрузки подтверждена. Наличие исходного
   снимка VirtualBox подтверждено владельцем; восстановление из него
   и финальный снимок не проверены исполнителем.
4. В журнале обновления были сообщения libselinux о несовпадении версий
   regex во время замены пакетов. Транзакция завершилась UPDATE_SUCCESS;
   после перезагрузки dnf check, restorecon и matchpathcon проходят,
   SELinux Enforcing, nginx работает, служб в состоянии failed нет.
5. dnf download первоначально скачал обе архитектуры tcpdump. Попытка
   установки обеих была отклонена до изменения пакетов из-за зависимостей
   i686. Затем выбран, проверен и успешно установлен только x86_64 RPM.

Пароли, приватные ключи и исходный shadow в репозиторий не включены.
Временное правило sudo без пароля удалено; сохранён обычный доступ
labadmin через wheel с запросом пароля и ранее настроенный SSH-ключ.
Ссылку на этот репозиторий владелец самостоятельно отправляет в LMS.
